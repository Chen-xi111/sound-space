# 第 3 步：数据结构与行为契约

文档版本：0.1 · 配置格式版本：1 · 更新日期：2026-10-06

状态：数据设计完成，附结构示例；现已实现正式 schema、校验器与首版音频核心，具体完成与待测范围见 [第 4 步报告](04-音频核心实现与验收.md)。

本文件承接 [需求文档](01-首版产品需求文档.md) 与 [技术目录](02-声音与技术功能目录.md)。冲突修订见 [审查记录](00-地基审查记录.md)。字段表和行为规则是后续实现约束，示例中的数值只是结构演示。

## 1. 核心对象与所有权

| 对象 | 职责 | 保存位置 | 是否随方案导出 |
|---|---|---|---|
| AssetRecord 素材记录 | 素材身份、修订、时长、授权、受信任资源定位 | 应用素材目录 | 仅引用，不导出音频或地址 |
| Recipe 方案 | 元数据、来源池、节律模式、阶段及来源说明 | 内置目录或本地个人库 | 是 |
| Layer 声音层 | 唯一层 ID 和固定声音来源 | 方案内部 | 是 |
| Stage 阶段 | 各层的完整参数、时长和包络 | 方案内部 | 是 |
| Draft 编辑草稿 | 尚未提交的完整方案、基础修订号、脏状态 | 本地草稿区 | 仅主动另存后导出 |
| Session 播放会话 | 启动快照、运行位置、时钟锚点、中断原因 | 内存为主，有限检查点 | 否 |
| Preferences 偏好 | 主音量、收藏、隐藏项、各场景默认配置 | 本地 | 否 |
| RecentEntry 最近使用 | 方案引用、实际开始时间、结束原因、快照摘要 | 本地，有数量上限 | 否 |

关系：一个方案拥有 1—4 层；一个阶段为每层提供且只提供一份状态。一个会话从方案的某个修订启动，持有独立快照；修改方案不会回写已启动的快照。

空白编辑器可以暂时没有层，但这种对象是未完成草稿，不能作为可播放方案保存或导出。带声音层的全静音阶段合法；完全没有声音层的纯计时器不属于首版。

## 2. 文件包与方案身份

首版导出一个方案一个 JSON 文件；不导出用户身份、历史、偏好、文件路径或素材二进制。

| 字段 | 类型 | 约束 |
|---|---|---|
| format | 固定字符串 | `wave-platform.recipe` |
| schemaVersion | 正整数 | 当前为 1；与产品 V1 和文档 0.1 无关 |
| exampleOnly | 布尔 | 结构夹具为 true；生产加载器拒绝播放 true 的文件 |
| recipe | Recipe | 完整配置 |

Recipe 字段：

| 字段 | 类型 | 约束／语义 |
|---|---|---|
| id | 字符串 | 不透明稳定 ID，不从名称推导 |
| revision | 正整数 | 同一个本地方案每次成功保存递增；新副本从 1 开始 |
| title / description | 字符串 | 标题 1—80 字符；描述最多 2,000 字符；按纯文本显示 |
| scenes | 枚举数组 | focus、study、relax、rest、sleep、custom；非空、去重 |
| createdAt / updatedAt | UTC ISO 8601 字符串 | createdAt 不晚于 updatedAt；显示时使用用户时区 |
| derivedFrom | null 或 {id, revision} | 记录来源，不形成内容继承关系 |
| capabilityProfile | 字符串 | 精确引擎能力版本；本轮示例为 `audio-v1-draft`，尚不可执行 |
| layers | Layer 数组 | 1—4 个，ID 唯一，顺序仅用于界面 |
| rhythm | 判别联合 | none、binaural 或 amplitudeModulation，见第 4 节 |
| timeline | 判别联合 | finite 或 continuous，见第 5 节 |
| completion | 对象 | {cue: null 或素材引用, gain: 0—1}；null 时 gain 必须为 0 |
| provenance | 数组 | 参数与元数据来源记录，见第 8 节 |

内置／个人／导入身份属于本地记录的 `origin`，不信任导入文件自报的身份。文件中的 ID 只用于来源记录，导入事务分配新 ID、revision=1、当前本地创建时间。即使与内置方案同名或同 ID，也不得覆盖。

## 3. 声音层：固定来源与阶段参数分离

Layer 只有 `id`、`label`、`source`。增益、启用状态等随阶段变化的值不再存一份层默认值，避免两处冲突。

| source.kind | 固定字段 | 语义 |
|---|---|---|
| noise | color、generatorVersion、seed、channels | color=white/pink/brown；channels=mono/independentStereo；seed 为非负 32 位整数 |
| binaural | oscillatorVersion、highEar | highEar=left/right；V1 波形为正弦，声道固定分离 |
| asset | assetRef、playback | assetRef={id,revision}；不含外部网址和本地路径 |

素材播放配置 `playback`：

| 分支 | 必填字段 | 约束 |
|---|---|---|
| mode=loop | startMs、loopStartMs、loopEndMs、crossfadeMs | 0≤loopStart≤start<loopEnd≤素材时长；0≤crossfade≤循环长度的一半 |
| mode=once | startMs | 0≤start<素材时长；播完后仅该层静音，阶段计时继续 |

每个 Stage 的 `layerStates` 都包含每层一次，字段为 `layerId`、`enabled`、`gain`、`params`。enabled 为布尔；gain 为 0—1 的数字增益。禁用时 gain 仍保留，输出为零，便于再启用。引擎不运行该层的声音源。

按来源类型限定 params：

| 来源 | params 完整字段 | 约束 |
|---|---|---|
| noise | pan、filter | pan∈[-1,1]；filter=null 或 {kind:lowpass/highpass, cutoffHz} |
| asset | pan | pan∈[-1,1]；V1 不设置素材变速、转调、节奏拉伸 |
| binaural | centerHz、beatHz | 二者有限且正；centerHz>beatHz/2；不允许 pan 或 filter |

双耳频率从中心与频差派生：低频=centerHz−beatHz/2，高频=centerHz＋beatHz/2；highEar 决定分配。频段标签和实际左右频率仅用于显示，不重复持久化。

滤波截止频率、载波上限、节律范围还必须满足第 4 步的 capabilityProfile 与实际采样率条件。仅通过正数检查不代表可播放；未知算法版本或未知能力配置必须阻止播放。

V1 每次进入阶段都从该阶段完整状态建立声音。素材从配置的 startMs 起播，噪声从保存种子起步，振荡器从确定相位开始；边界包络避免硬切。手动暂停／继续保留当前源位置；跳过、循环重新进入或异常恢复进入新位置时按本规则重新建立。跨阶段无缝延续同一首音乐不列入 V1，后续可增加显式连续性规则。

## 4. 节律模式与阶段参数

| rhythm.kind | 固定字段 | 不变量 |
|---|---|---|
| none | 无 | 不得含 binaural 层；每阶段 rhythmState=null |
| binaural | layerId | 恰有一个 binaural 层，引用指向它；每阶段 rhythmState=null，频率由该层 params 表达 |
| amplitudeModulation | targetLayerId、waveform | 没有 binaural 层；目标为 noise 或 asset；V1 waveform=sine |

AM 模式的每阶段 `rhythmState` 为 `{enabled, rateHz, depth}`，rateHz 为有限正数，depth∈[0,1]。处理器禁用时旁路，目标层禁用时不输出；该处理器仍属于方案结构，不能据此再加一个节律实例。

AM 包络采用不会增加目标信号绝对幅度的定义：`m(t)=1−depth/2 + (depth/2)sin(2π rateHz t)`。depth=0 是旁路，depth=1 的包络在 0 与 1 之间。V1 不做隐式响度补偿；启停处理和参数变化使用平滑控制。该定义是工程规范，不是疗效参数。

每阶段最多一个 AM 状态；全方案不能跨阶段切换 rhythm.kind。未来的 TMR、CLAS、40 Hz 专用协议需要新的格式／能力支持，V1 不将未知协议降级为普通音频。

## 5. 时间线和阶段

持久化时间统一为整数毫秒，频率为 Hz；界面可以显示分钟。毫秒在噪声脉冲、分钟计时等处始终表示时长，不表示刺激频率。

| timeline.kind | 字段 | 约束 |
|---|---|---|
| finite | repeatCount、stages | repeatCount≥1，代表整条阶段序列总共执行几遍；每阶段 durationMs>0 |
| continuous | stages | 恰好一个阶段，durationMs=null；不允许 repeatCount；用户明确选择持续播放 |

Stage 字段：`id`、`label`、`durationMs`、`fadeInMs`、`fadeOutMs`、`layerStates`、`rhythmState`。stage ID 在方案内唯一；阶段数组顺序就是执行顺序。

- 有限阶段 fadeInMs+fadeOutMs≤durationMs，包络计入时长，不另加时间。总时长=repeatCount×所有 durationMs 之和。
- 包络为阶段开始时 0→1、阶段结束前 1→0，中间保持 1；零包络长度不豁免引擎的去爆音处理。
- 持续阶段 fadeOutMs=0，不存在自然终点。用户停止时的平滑退出由引擎固定控制，不写成“无限时间减淡出长度”。
- V1 不做跨阶段时间重叠，避免下一段开始时间和总长度不确定。素材内部交叉淡化由素材循环规则管理。
- 延长当前阶段只改会话执行计划，不改已保存方案；仍可主动另存为方案。缩短若已越过新终点，则平滑进入下一阶段。
- 跳过即消耗本次阶段剩余时间，进入下一个实例；最后一个实例跳过后结束。未来循环中的相同 stage ID 不受本次延长影响。
- 正常完成才允许播放一次 completion 提示；手动停止、加载失败、系统异常和错过终点的恢复均不补播提示。
- continuous 的 completion.cue 必须为 null；完成提示使用引擎受控的短素材，不计作可编辑第五层，只在所有方案层退出后触发。

工程输入上限：每文件 1 MiB，最多 32 阶段，repeatCount≤100，有限总时长≤24 小时；持续模式另行表示。这些是 V1 的资源与输入限制，不是推荐聆听时长。

## 6. 运行会话、时间和播放权

Session 的必要字段：`sessionId`、`recipeSnapshot`、`sourceRecipeRef`、`state`、`stageIndex`、`iterationIndex`、`elapsedInStageMs`、`executionOverrides`、`audioAnchor`、`monotonicAnchor`、`deadlineUtc`、`interruptionReason`、`assetReadiness`、`ownerToken`。

recipeSnapshot 是启动时深拷贝的完整配方；临时音量／频率调整和延长存 executionOverrides，实际播放按快照＋经验证的覆盖解析。修改当前声音池或节律种类时创建新草稿并重新启动会话，不热替换结构。

| 状态 | 进入条件 | 离开规则 |
|---|---|---|
| idle | 无活动会话 | 用户点击开始或预听 |
| preparing | 校验配置、加载全部将启用的素材、申请播放权 | 全部就绪后 running；失败 error |
| running | 已有唯一播放权且音频正常 | 手动暂停 paused；中断 interrupted；停止 stopped；正常结束 completed |
| paused | 用户主动暂停，包括预听前暂停 | 时间冻结并释放播放权；用户继续时重新申请播放权、重建截止时间，不能自动恢复 |
| interrupted | 系统音频中断、失去播放权或素材错误 | 截止时间继续流逝；恢复先重算，到期 completed，否则用户确认后继续 |
| completed | 有限流程到期 | 再次播放必须创建新会话 |
| stopped | 用户停止或明确替换 | 取消排程、释放音源和播放权；重新开始创建新会话 |
| error | 配置、引擎或准备阶段失败 | 显示原因；修复后用户重新开始 |

时间策略：前台 UI 定时器仅刷新显示。音频事件按音频时钟排程；同一文档存活期间以单调时钟计算异常期间经过时间，UTC 截止时间用于显示与辅助检查，不因用户调系统时钟直接改变进度。页面被销毁、检查点丢失或时钟关系不可信时不恢复活动播放，只恢复配置。

用户手动暂停显式冻结流程；被动系统中断继续消耗当前执行计划。异常恢复若跨过若干阶段，则跳过它们，在当前应到阶段以剩余时长重新建立声音；新起播包络不延长原截止时间。不补播错过内容。

同标签预听也是短会话；保留原会话的手动暂停状态，预听结束释放音频资源，用户再决定是否继续原会话。跨标签使用可验证的排他播放权；若所选环境无法证明排他可靠，则采用阻止第二标签播放的降级方式，并写入支持矩阵。相关 API 与机制由第 4 步选型验证。

定时器被冻结时仍能截止、耳机变化能否检测、系统强制挂起后能否清理音频，都属于设备实测门槛，不把数据契约当成浏览器能力保证。

## 7. 素材目录与加载

AssetRecord 必填：`id`、`revision`、`category`（nature/music/cue）、`durationMs`、`channels`、`licenseStatus`、`licenseRef`、`resourceKey`、`contentHash`。本轮素材夹具允许未知值为 null，但标记 `fixtureOnly=true`，整体不可播放。

正式素材要有已确认授权、可解析资源、真实文件时长与内容校验值。resourceKey 只由应用信任的目录解析；来源说明链接可以给用户查阅，不能作为导入时自动获取资源的指令。

开始前解析所有阶段可能启用的来源和完成提示。任何必要素材缺失、版本不同、许可不可用或加载失败，都阻止完整方案开始。用户可主动生成删减后的副本；系统不能悄悄替代成相近雨声。所有阶段均禁用的素材层可保留编辑，但显示未使用且不下载。

素材版本固定引用；新版本不能自动替代旧版。无需音频素材的噪声／双耳方案仍需通过引擎能力检查。

## 8. 来源记录

provenance 项：`path`、`kind`、`referenceId`、`locator`、`note`。path 是相对 recipe 的 JSON Pointer；空字符串表示整个对象。kind 为 research、design 或 user。

采用最接近字段的祖先 path 记录作为该字段来源；精确字段记录优先于父对象记录。相同 path 不得有冲突记录，悬空 path 校验失败。

research 必须提供研究索引 ID 和方法段／表／页码等 locator；design 与 user 的 referenceId、locator 为 null。用户改变研究给定值后在该字段增加 user 记录，保留父级原始背景。研究链接和笔记仅为元数据，不决定运行权限。

根级来源记录是必填，确保所有字段都能继承来源；更细的字段记录可覆盖根级说明。本轮示例使用根级 design 记录，明确说明所有数值仅用于检查数据关系；不能因此标记为研究给定默认值。

## 9. 保存、草稿和偏好

本地逻辑存储区：personalRecipes、drafts、preferences、recentEntries、schemaMeta。具体数据库在实现阶段选型，但方案更新、revision 递增和索引更新必须原子提交。

草稿包含 baseRecipeRef 与 baseRevision。保存前比较当前修订；其他标签已更新时提示另存或解决冲突，不静默覆盖。写入失败保留内存草稿，显示未保存；从成功状态返回前必须确认提交完成。

从内置方案修改首次保存必须新建个人副本；个人方案再次保存递增 revision。删除个人方案不影响已启动的快照；恢复草稿或配置不自动出声。

Preferences 记录主音量、收藏／隐藏 ID、场景默认方案引用与界面偏好。最近记录上限建议 50 条，不保留逐秒行为日志；清理入口分别允许清除历史、个人方案或全部本地数据。完整清理先停止所有会话并释放播放权。

界面已隐藏的声音不参与自动推荐；收藏不自动删除。重复打开会话可恢复方案参数，但输出采用本机主音量策略；配置文件不能提高主音量或关闭输出保护。

## 10. 导入、兼容与迁移顺序

固定流程：检查文件大小 → 解析 JSON → 检查 format/schemaVersion → 结构与未知字段校验 → 引用与语义校验 → 引擎／素材能力检查 → 显示方案预览及可用性 → 用户执行导入 → 分配新身份并原子保存。

合法但缺少素材／引擎的方案可以存为“不可播放”，保留完整信息供修复；结构错误的文件不能成为已保存有效方案。exampleOnly 文件只作为开发文档夹具，不进入生产方案库。

- 当前同版本对象只接收声明字段，禁止未知枚举、非有限数值、非法联合分支、重复标识和悬空引用；不悄悄丢字段。
- 新于当前版本的文件不降级猜测，显示需要新版本；可保留原文件供用户自行保存。
- 旧格式仅通过明确、逐级、有样例覆盖的迁移转换；V1 首次发布不假设存在旧格式迁移器。
- 迁移先备份源记录，再转换、校验，全部成功才切换版本；失败回滚，原数据保持可读或可导出。
- 导入忽略外部身份特权，仅记录 derivedFrom；不自动请求文件中的网络资源，不改变本机设置。
- “往返恢复”保证配方配置与结构等价，不保证本地 ID、revision、创建时间、主音量、数字逐采样输出相同。

## 11. 错误分类与修复入口

| 错误码 | 原因 | 行为 |
|---|---|---|
| FORMAT_INVALID | 文件类型、大小、字段或数字非法 | 拒绝导入，定位字段 |
| VERSION_UNSUPPORTED | 未支持的格式版本 | 不转换猜测 |
| REFERENCE_INVALID | 层／处理器／阶段引用不成立 | 阻止保存有效方案 |
| RHYTHM_CONFLICT | 多个双耳层、双耳与 AM 共存 | 引导移除或替换 |
| TIMELINE_INVALID | 持续模式混循环、负时长、包络越界 | 返回具体阶段 |
| CAPABILITY_UNAVAILABLE | 算法、采样率、参数范围或输出不支持 | 保留配置但阻止播放 |
| ASSET_UNAVAILABLE | 素材缺失、版本不符或许可未确认 | 重试或显式编辑副本 |
| PLAYBACK_OWNED | 另一会话／标签持有音频 | 不叠加，提示处理已有会话 |
| SAVE_CONFLICT / SAVE_FAILED | 修订冲突或本地写入失败 | 保留草稿，不标保存成功 |

## 12. 五个结构示例

| 示例 | 覆盖路径 | 可用性 |

## 13. 第 4 步的实现交接

先将本契约落实为正式 schema／类型和语义校验器，再实现单会话音频内核。后续测试直接覆盖下表，当前只做配置级校验。

| 用例 | 期望 |
|---|---|
| 四层合法／第五层 | 前者接受，后者拒绝 |
| 两个双耳层，或双耳＋AM | 即使其中一个静音也拒绝 |
| AM 指向不存在层／binaural 层 | 拒绝 |
| 阶段漏层、重复层、错误 params | 拒绝，不继承上一阶段 |

| 循环区域越过素材时长／交叉淡化超半个循环 | 拒绝 |
