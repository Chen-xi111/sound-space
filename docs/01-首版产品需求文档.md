# 首版产品需求文档

版本：0.2 · 更新日期：2026-10-06 · 状态：经设计审查修订；配套数据契约见第 3 步文档

本文完成 workflow 第 1 步。技术类型、参数与组合约束见 [声音与技术功能目录](02-声音与技术功能目录.md)。本文的验收条件供后续软件交付使用，本文是需求基线；当前实现进度见 [音频核心实现与验收](04-音频核心实现与验收.md)。

## 1. 产品定位与目标

构建一个多用途声音组合平台，让用户根据当前任务、声音偏好、播放设备和可用时间，选择或制作适合自己的声音环境，并能保存、重复使用。

核心流程：选择目标 → 选择方案 → 调整声音与时长 → 开始使用 → 保存或再次使用。

使用已有研究作为声音类型与方案设计的来源。首版不安排科研复现、认知测验或功效实验；用户不需要完成问卷才能播放。

首版要完成的产品价值：

- 一个入口覆盖日常学习、工作、休息及睡前声音需求。
- 内置方案可以一键播放，也可以展开为可编辑的声音组合。
- 通过阶段流程衔接学习与休息、睡前放松与渐弱结束。
- 保存个人版本，下次能恢复同一组合及其设置。

首版面向成年人日常使用。儿童场景、疾病治疗流程及临床管理不在当前产品范围内。

## 2. 平台与版本约定

2026-10-10 范围调整：当前面向电脑开发和验收。保留可适应不同窗口尺寸的界面，但手机、锁屏与移动端打包不作为本阶段任务。音频核心与界面继续分离。

本地生成的声音与素材音频统一进入混音引擎。首版支持本地保存方案和偏好，不要求注册，不上传用户使用历史。声音素材可能需要首次联网加载；首版不承诺完整离线使用。

验收聚焦桌面播放、窗口切换、音频中断恢复与稳定性；手机锁屏不列为阻塞项。

本文的范围标记：

| 标记 | 含义 |
|---|---|
| V1 | 首版交付范围，按前后依赖逐步实现 |
| V2 | 首版稳定后扩展，不作为首版完成条件 |

## 3. 六个使用入口

| 入口 ID | 入口 | 场景 | 主要配置与行为 | 范围 |
|---|---|---|---|---|
| SC-01 | 专注 | 阅读、写作、编程、重复工作 | 选择声音方案，设置持续时间；允许用户主动选择不限时 | V1 |
| SC-02 | 学习 | 背词、复习、解题、理解材料 | 学习／休息阶段模板、循环次数、安静休息选项 | V1 |
| SC-03 | 放松 | 工作结束、精神紧绷、睡前过渡 | 自然声与音乐方案，简单混音、淡入淡出 | V1 |
| SC-04 | 休息 | 工作间隙、闭目休息 | 短时流程，选择静默结束或提示音 | V1 |
| SC-05 | 睡前／睡眠 | 睡前放松、入睡背景 | 定时、渐弱、可关闭视觉界面；持续播放由用户主动选择 | V1 |
| SC-06 | 自由组合 | 自定义个人声音环境 | 从空白或已有方案创建最多四个声音层，保存个人版本 | V1 |

六个入口共享方案库与播放引擎，不各自维护一套播放器。同一方案可以属于多个场景。

学习入口首版提供声音和时间安排；学习卡片、知识内容管理、睡眠记忆提示属于 V2 的 TMR 相关工作，不在首版暗中扩展。

## 4. 主要用户流程

### UF-01：第一次开始播放

1. 用户选择目标，看到适用方案；无需登录或填写问卷。
2. 方案卡片展示声音组成、时长，以及必要的耳机条件。
3. 用户点击开始；由这次明确操作启动音频，不自动播放。
4. 播放页提供主音量、计时和声音比例调整。
5. 结束后可以收藏或保存修改；不强制评分。

### UF-02：修改内置方案并保存

1. 从播放页进入编辑器，当前组合保持可见。
2. 用户调整声音层、参数或播放阶段。
3. 点击保存，输入名称，生成个人副本；内置原件不变。
4. 未保存就离开时，允许保存、放弃或继续编辑。
5. 下次打开个人副本，恢复完整方案，不自动开始播放。

### UF-03：执行学习／休息流程

1. 选择模板，调整各阶段时长和循环次数。
2. 确认结束提示方式，开始第一阶段。
3. 系统平滑切换声音；休息阶段也可完全静音。
4. 用户可以暂停、跳过或延长当前阶段。手动暂停冻结流程；异常中断的恢复规则见第 7 节。
5. 最后一阶段结束后停止，不自动进入无限循环。

### UF-04：睡前使用

1. 选择背景，明确播放时长或主动选择持续播放。
2. 定时方案显示何时开始渐弱、何时结束；不限时方案没有隐含结束时间。
3. 开始后可进入低亮度、简化显示。
4. 电脑进入睡眠或音频中断后明确显示会话状态；恢复时遵循暂停与到期规则。
5. 到时平滑结束，默认无结束提示音。

### UF-05：重复日常使用

1. 首页展示最近使用与收藏。
2. 用户打开方案，恢复上次保存的配置。
3. 用户确认开始；恢复设置本身不触发出声。

## 5. 首版功能与完成标准

| 需求 ID | 功能 | 具体范围 | 完成标准 |
|---|---|---|---|
| FR-01 | 场景导航 | 六个入口、最近使用、收藏 | 每个入口都能找到方案并进入同一播放流程 |
| FR-02 | 方案库 | 用途、声音类型、时长、耳机条件筛选；名称搜索 | 筛选组合正确；无结果时可清除筛选，不显示伪造推荐 |
| FR-03 | 方案详情 | 组成、时长、设备条件、来源与参数说明 | 用户开始前能识别所需设备和播放方式 |
| FR-04 | 播放控制 | 开始、暂停、继续、停止、主音量、定时 | 同一时间只有一个活动播放会话；停止释放对应音频资源 |
| FR-05 | 组合编辑 | 最多四层；添加、移除、静音、单层音量 | 编辑与实际声音一致；超过上限时不静默丢弃音轨 |
| FR-06 | 基础声音 | 白／粉红／棕噪声、自然声、音乐 | 生成与素材播放统一混音，声音切换没有明显断点 |
| FR-07 | 高级节律 | 双耳节拍或振幅调制；参数分组展示 | 全方案最多一个双耳节拍层，或一个振幅调制处理器，两者互斥 |
| FR-08 | 阶段流程 | 阶段增删排序、时长、循环次数、过渡、延长与跳过 | 暂停后计时冻结；恢复后衔接剩余时长；结束行为符合设置 |
| FR-09 | 个人方案 | 复制、保存、重命名、收藏、删除 | 个人副本与内置方案独立；删除有可撤销或明确确认机制 |
| FR-10 | 本地持久化 | 方案、偏好、有限的最近使用记录 | 重开页面可恢复；存储失败明确提示，不假装已保存 |
| FR-11 | 基础个性化 | 按场景、耳机条件、时长、收藏与历史排序 | 用户能隐藏声音；隐藏项不再主动推荐；无需测验或问卷 |
| FR-12 | 导入导出 | 方案配置文件，包含格式版本与素材引用 | 可往返恢复；不支持的版本或缺失素材明确显示，不静默替换 |
| FR-13 | 设置与说明 | 默认时长、结束提示、数据清理、素材及来源说明 | 用户可清除本地记录；不把数字音量显示成未经校准的声压级 |
| FR-14 | 内置内容 | 首批 12—18 个方案，覆盖六入口主要场景 | 每个方案均有完整配置、简短说明、来源及明确使用条件 |

阶段编辑器与单次播放共用同一音频引擎。高级参数默认折叠；用户能只用基础操作完成全部常见流程。

## 6. 首版页面与内容

| 页面 | 主要内容 | 关联需求 |
|---|---|---|
| 首页 | 六入口、最近使用、收藏、继续配置 | FR-01、FR-11 |
| 方案库／详情 | 筛选、搜索、组成与使用条件 | FR-02、FR-03、FR-14 |
| 播放页 | 状态、计时、音量、快捷混音、当前阶段 | FR-04、FR-08 |
| 组合编辑器 | 声音层、节律、阶段配置、保存 | FR-05—FR-09 |
| 我的方案 | 收藏与个人副本、重命名、导入导出 | FR-09、FR-10、FR-12 |
| 设置与说明 | 播放偏好、本地数据、来源信息 | FR-13 |

界面以中文为首版语言，保留常见技术英文名；正式品牌名后续可替换。视觉设计在第 5 步完成。

内容安排建议：专注 3 个、学习 3 个、放松 3 个、休息 2 个、睡前／睡眠 3 个，共 14 个初始方案；自由组合提供空白入口及复制已有方案的入口，不额外凑数。具体名称、素材与参数在第 6 步确定，14 个为内容规划值。

## 7. 播放与数据行为约定

- 初次访问不自动出声。恢复历史或导入文件也不自动播放。
- 切换方案时先明确处理当前播放，避免后台叠加多个完整会话。
- 音量和频率等参数变化采用平滑过渡；时间参数变化保持可理解的剩余时间显示。
- 达到数字峰值上限时由输出管理处理，不能仅依赖用户自行降低每层音量。
- 有限流程使用明确截止时间；用户手动暂停冻结剩余时间，显式继续后重建截止时间。系统音频中断或页面失去控制不视为用户主动暂停，截止时间继续流逝。
- 后台但音频仍在正常运行时保持调度；异常恢复时先关闭输出并重算位置，到期即结束，未到期等待用户点击继续，不补播错过的阶段或提示音。持续播放没有截止时间，但异常恢复仍须显式继续。
- 页面关闭后只恢复草稿、方案和历史，不承诺恢复一段已经失去控制的音频会话。若设备时钟变化或丢失状态导致无法确定位置，保持停止，让用户重新开始。
- 定时结束必须在音频时钟上预先安排；不能只依赖页面定时器。浏览器／系统能否保障这一行为仍需第 4 步实测，未通过的环境不能标为支持可靠睡眠定时。
- 耳机移除或输出设备变化时，在系统能够检测的范围内暂停或提示；各平台实际能力写入支持矩阵。
- 素材加载失败时显示对应层的状态并提供重试，不把缺失声音的组合标为完整成功。
- 导出仅包含配置与素材引用；不自动打包或传播受限音乐文件。
- 浏览器本地数据可能被用户或系统清理；通过导出提供备份路径。首版没有云端恢复承诺。
- 来源详情区分研究方法中的参数、产品设计默认值和用户修改值；正常播放界面保持简洁。
- 方案预听与正式会话共用唯一播放所有权。正式会话正在播放时先明确暂停再预听，结束预听后不自动恢复；其他标签页也不能同时持有播放权。
- 开始会话前检查该流程所有会启用的素材；缺失时阻止开始，允许用户明确移除／替换后生成新方案。运行中丢失必要素材时中断整段会话，不悄悄少播一层。
- 隐藏声音影响自动推荐；用户收藏的原方案仍可找到，显示包含已隐藏声音，不擅自改配方。
- 主音量属于本机播放偏好，初次启动采用引擎保守默认值；方案保存的是各层相对音量。导入配置不得更改本机主音量、输出保护或直接触发播放。
- 首版不限制多层背景声，但全方案仅允许一个双耳节拍层或一个振幅调制处理器；阶段中也不能绕过这一数量约束。
- 方案文件只引用受信任内置目录中的素材标识与版本；不根据导入文件中的网址、路径或脚本自动下载或执行内容。导入生成新的本地身份，不覆盖同名／同 ID 的现有方案。

## 8. 首版以外的功能

| 范围 | 功能 | 原因／前置条件 |
|---|---|---|
| V2 | 账户、云同步、公开分享链接 | 先稳定本地方案模型与隐私设置 |
| V2 | 完整离线素材包、音频文件导出 | 需要缓存策略、存储配额和素材授权处理 |
| V2 | TMR 学习内容与提示音绑定 | 需要独立内容流程及睡眠提示播放条件 |
| V2 | 40 Hz 独立音频模块 | 与普通背景方案分离，单独定义参数和用途 |
| V3 | EEG＋CLAS、声光同步 | 需要选定设备、实时数据与时序控制 |
| 暂不纳入 | 社区、创作者市场、订阅付费、生成式音乐服务 | 不影响首版完整使用流程，避免分散开发 |
| 暂不纳入 | 自动诊断、认知评分、治疗流程、科研功效试验 | 不属于当前用户授权的建设目标 |

首版不包含用户任意上传音乐文件；先使用来源清楚的内置素材。后续需要时可单独加入本地文件导入。

## 9. 开发依赖与软件验收

推荐依赖顺序：功能基线 → 技术目录 → 数据模型 → 音频核心与后台播放检查 → 页面 → 内容 → 阶段调度 → 本地管理与推荐 → 集成检查。

数据模型需要同时支持单层／多层、单阶段／多阶段，避免第 7 步增加阶段流程时推翻前面的保存格式。

| 验收 ID | 软件验收项 | 可观察结果 |
|---|---|---|
| AC-01 | 首次使用 | 从目标入口到播放，无登录与测验阻断 |
| AC-02 | 方案保存 | 修改后保存、关闭、重开，声音层与参数完整恢复 |
| AC-03 | 声音正确性 | 频谱、声道分离、节律和调制深度与配置对应 |
| AC-04 | 混音质量 | 常见组合不削波，循环和切换无明显爆音 |
| AC-05 | 阶段调度 | 暂停、延长、跳过、结束均与界面时间一致 |
| AC-06 | 设备兼容 | 记录桌面目标环境的播放、窗口切换、睡眠和音频中断行为 |
| AC-07 | 文件交换 | 有效方案导出后可导入恢复，错误文件有明确提示 |
| AC-08 | 易用性 | 小屏可操作，主要控件支持键盘，状态不只靠颜色表达 |
| AC-09 | 数据可控 | 本地记录可清理，失败状态可见，无未经声明的使用历史上传 |
| AC-10 | 内容完整 | 12—18 个可用内置方案，全部素材来源可追溯 |

上述项目属于软件和音频质量检查，不用于检验论文结论。

## 10. 进入第 3 步的交接项

第 3 步应设计声音素材、声音层、节律处理、阶段流程、方案、播放会话与用户偏好的关系，以及格式版本、缺失素材、导入验证和个人副本规则。

以下事项按后续步骤解决，不阻塞当前规划：

| 事项 | 当前处理 | 解决节点 |
|---|---|---|
| 正式产品名、视觉风格 | 使用项目工作名，中文界面 | 第 5 步 |
| 具体前端与音频实现方案 | 保持声音引擎与界面分离 | 第 3—4 步 |
| 默认声音参数和调节边界 | 按来源分类，尚未定具体数值 | 第 4、6 步 |
| 背景与音乐素材选择 | 仅用自有／明确授权素材 | 第 6 步 |
| 目标浏览器支持矩阵 | 当前仅以桌面为目标，移动端暂不进入开发范围 | 第 4 步 |
| EEG 设备和声光硬件 | 不预先绑定品牌或接口 | 第 10 步 |

第 1 步完成情况：六个入口、五条主流程、14 项首版功能、范围排除项与软件验收条件均已定义。0.2 补齐计时、导入、预听及素材缺失规则。字段与状态约束以 [数据结构与行为契约](03-数据结构与行为契约.md) 为准；修订记录见 [地基审查记录](00-地基审查记录.md)。
