# 第 1—3 步设计审查记录

更新日期：2026-10-06。审查对象是功能与数据设计；未进行科研复现，也未实施音频运行测试。

## 审查发现与处理

| 编号 | 原有缺口 | 已采用的修订 | 后续验证 |
|---|---|---|---|
| R-01 | “一种节律类型”仍允许多个同类双耳层 | 一个双耳层或一个 AM 处理器；即使静音仍计数 | 组合语义校验 |
| R-02 | 暂停冻结与挂起后到期规则有歧义 | 区分手动暂停、系统中断、后台正常运行、页面重载 | 状态机与设备测试 |
| R-03 | 阶段是否继承参数、四层是同时还是全局不明 | 四层全局池，每阶段完整状态，进入阶段重新解析 | 跳过／循环用例 |
| R-04 | 预听可能与正式播放或其他标签页叠加 | 全局播放所有权，预听前显式暂停，结束不自动恢复 | 多标签与预听用例 |
| R-05 | 保存方案与本机主音量混在一起 | 配方存层增益，主音量与输出保护留在本机 | 导入不改变本机设置 |
| R-06 | 导入可能覆盖现有身份或加载外部文件 | 配置包新建本地身份；只解析目录引用，不跟随外部素材地址 | 冲突与未知素材用例 |
| R-07 | 音乐播完是否终止会话、素材缺失如何处理不明 | 播完只结束该层；缺失必要素材阻止开始／中断播放 | 单次素材和加载失败 |
| R-08 | 内置更新、个人副本、会话和草稿关系缺失 | 修订号、独立副本、不可变启动快照、临时运行调整分离 | 更新期间播放与保存 |
| R-09 | 无期限、循环、阶段长度、渐弱尚无共同约束 | 有限／持续互斥；所有持久化时间统一整数毫秒 | 示例与边界检查 |
| R-10 | “参数来自研究”没有逐字段出处规则 | 来源记录指向具体字段；示例标为结构占位，正式内置参数逐项标注 | 第 6 步参数表 |
| R-11 | 未定义版本迁移、坏文件与存储失败 | 严格版本识别、事务提交、原文件保留、失败不标成功 | 迁移与失败用例 |
| R-12 | 定时关闭可能仅依赖被冻结的 UI | 截止动作交给音频调度；支持范围由实测决定 | 第 4 步后台定时门槛 |

## 配置检查结果

使用临时检查脚本对实际 JSON 文件执行结构与关键语义检查，未将脚本作为生产校验器加入项目。

| 项目 | 结果 |
|---|---|
| 5 个正向配置示例 | 全部通过本轮结构检查 |
| 总时长计算 | 专注 25 分钟；学习／休息循环 60 分钟；双耳组合 10 分钟；睡前组合 20 分钟；持续背景无截止时长 |
| 16 个非法配置变体 | 全部被临时检查拒绝 |
| 素材占位状态 | 两个占位素材均无资源和授权，被明确标为不可播放 |
| 本地 Markdown 链接 | 全部目标存在；未对外部研究链接重新联网验证 |

16 个反向用例覆盖：第五层、第二个双耳层、双耳与 AM 同时存在、AM 目标丢失、阶段漏层、阶段重复层、负时长、持续模式附带循环次数、持续模式附带有限时长、包络超时、素材循环越界、循环交叉淡化过长、导入外部资源地址、双耳载波与频差冲突、非有限增益、来源字段引用丢失。

这些结论只说明第 1—3 步设计和示例通过当时检查，不保证未来实现无缺陷。后续已生成 schema、校验器与音频核心，实际验证范围见 [第 4 步报告](04-音频核心实现与验收.md)。
