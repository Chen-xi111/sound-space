# 第 4 步：配置校验与音频核心

更新时间：2026-10-06。

状态：核心代码、工程调试页和自动检查已完成；本地服务已成功启动，本机 Chromium 浏览器的核心流程已实测。手机后台、锁屏与真实设备中断仍待验证。第 4 步不标记为全部验收通过。

## 1. 运行方式

在项目根目录使用 Node.js 22 或以上版本，无需安装第三方依赖：

```sh
npm test
npm start
```

默认地址为 `http://127.0.0.1:4173`，服务只监听本机，不发布到互联网。若需改变端口，可在启动时设置项目专用变量 WAVE_PORT。调试页包含六种工程声音配置、播放控制、配置检查和静音自检；尚不是第 5 步的正式产品界面。

不要直接双击 HTML 代替本地服务，模块加载与音频工作线程需要正确的网页上下文。

## 3. 已实现能力

- 白／粉红／棕噪声实时生成，确定性随机种子，单声道或独立双声道。
- 双耳正弦载波左右分离，载波和频差独立配置。
- 单层正弦振幅调制，深度为 0 时旁路，不做隐式增益补偿。
- 噪声的一阶低通／高通滤波、声像及最多四层混音。
- 素材单次播放、循环与交叉淡化；素材播完只结束该层。
- 有限／持续时间线、静音阶段、整个序列重复、跳过和延长当前实例。
- 主音量和当前阶段层音量的平滑调整；阶段参数切换经包络处理。
- 采样线程决定阶段边界与自然截止，不依赖 UI 的计时刷新；完成提示也在采样线程中安排。
- 手动暂停保留源状态并冻结进度；被动中断后按经过时间重新定位，必须显式继续；过期不补播。
- 配置、素材或工作线程错误不会被静默转换成缺层播放。
- 正式会话使用启动快照；准备期间用户修改原配置不影响该快照。

这里实现的是数字信号和软件行为。尚未进行扬声器／耳机实听、移动设备后台或锁屏测试。

## 4. 当前引擎参数与版本

| 项目 | 当前实现 | 定位 |
|---|---|---|
| capabilityProfile | audio-v1-core | 仅这一能力版本可播放 |
| 噪声算法 | noise-v1 | 白噪声 PRNG、Voss 类粉红近似、带泄漏的棕噪声积分 |
| 振荡器 | sine-v1 | 正弦生成，左右独立频率 |
| 双耳中心载波 | 80—1000 Hz | 工程输入边界，不是最佳功效范围 |
| 双耳频差、AM 速率 | 1—30 Hz | 当前模块范围；不开放 40 Hz 专用协议 |
| 滤波截止 | ≥20 Hz，且小于 20 kHz 和采样率 45% 中的较小值 | 工程边界 |
| 主音量 | 初始 20%，0—100% | 本机数字增益，不对应校准声压级 |
| 输出管理 | 固定 1/4 混音余量，最终样本限幅 ±0.95 | 不因删掉一层而提高其他层音量 |
| 控制平滑 | 约 20 毫秒 | 极短阶段按长度压缩包络；不延长截止时间 |
| 配置输入 | 1 MiB、32 阶段、100 次循环、有限总时长≤24 小时 | 防止错误配置占用过多资源 |
| 单个素材 | 文件≤16 MiB，解码后≤64 MiB | 当前内存边界，非完整素材包方案 |

粉红和棕噪声是有限采样率下的工程近似。本轮频谱测试检查低／高频能量的相对变化，未进行全频带声学校准或证明每个频点严格符合理论斜率。

根级参数来源记录现在是必填，字段级记录可以覆盖根级说明。它补齐了第 3 步中“每个参数都必须有来源”的可执行约束。

## 5. 素材与输入处理

调试页仅附带一个本项目自行生成的两秒测试音，未引入第三方音乐或自然录音。来源说明见 [素材说明](../public/assets/SOURCE.md)。第 6 步再准备正式素材库。

配置中只接受素材 ID 和版本，实际资源地址由应用内置目录解析。加载流程包括：授权状态检查 → 目录定位 → 限量读取 → SHA-256 比对 → 解码 → 时长、声道和内存检查。

第 3 步的五个 exampleOnly 配置依然拒绝播放；其中的素材占位文件没有被升级成真实素材。未知能力版本与缺失素材可以表示“结构合法但不可播放”，不会被自动替换。

导入文件的持久化、自动分配新身份、草稿冲突和云同步不是本步实现内容，分别留给后续个人方案管理步骤。调试页的“播放此配置”只在当前会话使用，既不保存也不覆盖任何用户方案。

## 6. 自动检查与发现的修复

本轮 `npm test`：85 项通过，0 失败。机器输出保存在 [node-tests.tap](verification/node-tests.tap)。

| 类别 | 覆盖内容 | 验证方式 |
|---|---|---|
| 配置 | 原有示例、合法四层、第五层、同类节律叠加、悬空引用、未知字段、非法时间、版本和来源 | 实际 JSON 与变异配置 |
| 采样 | 44.1/48 kHz、不同块长度、到期零输出、静音阶段、噪声谱趋势、双耳频率、AM 包络、混音上限 | 直接离线运行与工作线程共用的 DSP |
| 素材 | 目录与真实 WAV 一致、正确哈希、损坏文件、缺失资源、解码不一致、超限、取消 | 真实测试文件与受控网络／解码替身 |
| 生命周期 | 快速重复启动、准备期取消、暂停保留、被动中断到期、恢复定位、错误清理 | 浏览器 API 替身与受控时钟 |
| 播放权 | 第二实例拒绝、释放后接管、申请取消、不支持 API 时拒绝 | 受控 Web Locks 替身 |

测试期间修复了以下实际问题：

1. 跳过阶段误将采样帧作为毫秒传入定位接口。
2. 未来阶段仍引用调用方可变对象，违背会话快照独立性。
3. 暂停等待期间处理器失败，清理与暂停续体竞争导致空对象访问。
4. 准备期间和停止后的延迟结果需要 generation 标识，避免重新连接旧会话。
5. 跳过发生在自然边界附近时，淡出结束不应再回跳到已经越过的阶段边界。
6. 真实浏览器发现：中断到期后虽然停止播放，进度仍显示中断时位置。已统一更新为总时长，并显示“流程已结束”。
7. 恢复流程等待播放权或音频设备时，可能在等待期间到期。现在恢复后再次核对截止时间，过期不补播；未到期按设备实际恢复后的时间定位。新增四项回归检查，并使完成后的迟到消息不能回写旧进度。

自动检查只说明被测试的代码路径通过；API 替身通过不等于浏览器行为通过。
